# Nov 2 stage — streaming ingest, ezrules proxy, RQ3

Plan row: DESIGN.md §9, Nov 2 (non-stretch; Spark Open + Glimmer
distillation bypassed per author call). Two deliverables: the live
scoring path (streaming graph → engine → proxy) and the RQ3 latency
table. No matcher/compiler semantics changed; no live ezrules in this
pass (proxy validated against a stub upstream, RQ3 baseline is a
labeled SQLite proxy).

## 1. What was built

`src/motifql/graph.py` — streaming appends. Attribute arrays are
over-allocated (geometric growth; the `times`/`frm`/… attributes are
read-only views of the live prefix, so every existing reader works
unchanged). The CSR stays frozen; post-CSR edges live in per-node
overflow lists that `incoming`/`outgoing` merge with the CSR slice
(oldest-first via insertion at `searchsorted(..., side="right")` —
overflow positions always exceed CSR positions, so ties order
CSR-first). `rebuild()` (auto past `rebuild_threshold` appends, or
explicit) re-runs `_csr` over all edges with stable node ids, and
`empty()` builds an edge-free graph for live-only use. Overflow is
watermark-filtered on read, so eviction semantics hold for both stores.

`src/motifql/engine.py` — `Engine(motifs)`: compile once (parse → check
→ plan), `score(transfer)` appends and anchors every motif
(thread-safe via one lock), `replay(frame)` batch-scores for parity.
Transfer contract: prep-schema fields, timestamp as epoch/ISO/datetime,
`transfer_id` optional (counter continues past explicit ids). Results
carry score, top_score, witness (transfer-level dicts), explanation
(predicate/degree/step), truncation and expansions.

`src/motifql/proxy.py` + `server.py` — FastAPI service (`fastapi`,
`uvicorn`, `httpx` added). `POST /score` scores one transfer;
`POST /evaluate` scores the transfer in `event_data`, injects
`event_data.motifs = {name: top_score}` and forwards to the upstream
(stock ezrules `/api/v2/evaluate` shape, URL from env/flag).
`top_score` (not emit-gated `score`) is injected so rules can cut below
the motif emit. Dead upstream → 502 with the scores and the error, so
the engine's view is never silently lost. `GET /healthz`, plus a typer
CLI (`python -m motifql.server --motifs … --data … --upstream …`).

`eval/rq3.py` — serial per-anchor timing over a seeded holdout sample:
pruned + exact-floor arms per motif, unpruned on a sub-sample (path
motifs only), and a SQLite bounded-BFS arm (depth 3, 7d window, 10K
node cap) as the ezrules-SQL-BFS proxy. Kernels are warmed up per
plan/mode before timing, so the one-time load cost is excluded.

Rebased onto #19 (numba fast paths) with the overflow guard its PR
description specifies: `csr_ordered` reads False while appended
transfers sit in the overflow, so live scoring runs the Python
reference until `rebuild()`; `_STRUCTURE` tracks the backing arrays
`append`/`_grow` actually rebind. Covered by two fast-vs-Python
field-for-field tests with appends (existing + new nodes, in-order +
out-of-order), before and after `rebuild()`.

Tests: `test_streaming.py` (8: merge order, batch parity over every
windowed query, new accounts, rebuild stability, empty, eviction,
out-of-order, full score parity path+group), `test_engine.py` (4:
contract, witness, live-vs-replay, rejection), `test_server.py` (6:
TestClient shape/injection/forwarding/502/422). Real-socket uvicorn
smoke via `/tmp/serve_smoke.py` (throwaway, not committed).

## 3. Reading the numbers

- **Replay clears by ~700×; live clears by ~15× — over the peak
  minute.** Summed serial means over all 8 motifs ≈ 84µs/transfer
  (~11.9k transfers/sec single-core). The load baseline is the
  busiest minute, 995 transfers (Sep 9 00:21) = 16.6/s — not the
  7.6/s peak-day average the first draft used (654,467/day ÷ 86,400).
  Against the peak minute: replay ~700×, live ~15× (live runs the
  Python reference while overflow is pending — the pre-#19 code path
  at ~4.1ms/transfer, ~245/s, measured on this same sample before
  the rebase). Against the peak-day average the figures are ~1500×
  and ~32×. The p99 tail is scatter_gather (119µs); everything else
  is ≤91µs. Making the kernels read the overflow (~0.16ms live,
  per #19) is an explicit follow-up.
- **Outputs are unchanged by the speedup.** Every truncation rate,
  mean-expansions figure and fire count in this table matches the
  pre-#19 run on the identical sample exactly.
- **Pruning is load-bearing, and exact.** Unpruned search is 7–15×
  slower per anchor *and* truncates (6% on layering — lost positives),
  while exact-floor top_scores agree with unpruned at 1.0000 on both
  path motifs. This is the RQ2 exact-floor choice paying off twice:
  ranking-correct and live-fast.
- **The BFS proxy comparison is now lopsided.** The slowest motif
  (scatter, 61k/s) runs ~1800× the BFS proxy throughput (34/s) at
  ~79× better p50, and no motif p99 is within an order of the BFS
  p99 (314ms). The proxy is honest about what it is: same shape as
  ezrules' feature (undirected BFS, SQL per event, node cap), not
  ezrules itself.
- **Truncation concentrates where expected:** fan_out/gather share the
  10.1% (sender-side hubs), butterfly 15.5% (pair budget) — all flagged
  per-result, none failing.
