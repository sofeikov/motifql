## 9. Methodology disclosures (C, D)

C (holdout as dev set): confirmed from committed docs — Oct 30 §3
labels its holdout table "tuning input for Nov 1", §8 picks
layering for recalibration from holdout numbers, and the emit flip
plus `*5..8` refit were made with holdout degrees on screen. Each
change has a train-only justification giving the same value, so
bias is probably modest, but "all fits on train" was false and no
untouched test set remains. Mitigation: this report discloses per
change; the α=emit default uses no new fitting; a frozen test
split is scheduled before any further tuning.

D (fragmented ground truth): verified — 88/370 HI instances touch
≤2 accounts (my count matches the audit); 24/29 completable
holdout instances touch ≤2 accounts (audit). Prep is faithful
(generator headers say "Max 1 hops"); eval wrongly treats every
block as an independent typed instance. "3/3 CYCLE" says nothing
about multi-hop cycles — all 3 holdout CYCLEs are A→B→A. No fix
in this pass; the overlap analysis (§4) and per-instance counts
are the honest lenses until instance modeling is revisited.
