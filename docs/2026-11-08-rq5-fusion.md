# RQ5-lite: hybrid motif + GBM fusion (#21)

`eval/rq5.py`. Status: run on HI-Small holdout; verdict negative at
operational budgets — reported plainly per the acceptance criteria.

## 1. Verdict

Neither fusion beats either alone where it matters. At 50 alerts/day,
min-rank fusion lands between the two parents on transfers (102 vs 128
GBM / 88 motif union) and below the motif union on completable
instances (5 vs 8, best single 15). Stacked GBM is worse on both
(99 transfers, 2 instances). The split verdict from the issue-15
report stands: transfers go to the GBM, instances to the motifs, and
naive fusion splits the difference instead of combining the strengths.
No README change: the hybrid does not win at the operational budget.

The one bright cell is fusion at @500 instances (23 vs 21 union, 10
GBM) — but it loses transfers there 388 vs 525, so it is a tradeoff,
not a win.

## 2. Method

Two arms, both ranked per day through `eval/evaluate.py`:

* **fusion_minrank**: min-rank union of {3 motif fuzzy scores +
  gbm_own} via the newly extracted `eval/union_rank.min_rank_union`
  (the CLI now calls the same function; it reproduces 88/123/173
  exactly). No fitting.
* **stacked**: gbm_own's 27 features (18 window + 7 format + 2 own)
  plus 3 motif top_scores, retrained train-only with the same
  hyperparameters/seed (`eval/supervised.train_gbm`, extracted so
  both call sites share one definition). Fit Sep 3–6, val Sep 7,
  holdout Sep 8–10. Truncated flags omitted: holdout scores carry
  none, and truncation is 0.00/0.00/0.00% on the fresh train replay.

Data assembly: motif holdout scores (`rq2_holdout_scores.parquet`)
and GBM holdout scores (`supervised_scores.parquet`, `score_gbm_own`)
both cover exactly the 1,345,565 holdout transfer ids in filter
order, with saved days agreeing with `transfers.parquet` — the
joins line up, verified by id-set assertions in `rq5.py`, not
assumed. Instance splits recomputed from `eval/splits.py`.

Train motif scores could not be reused: `rq1_train_scores.parquet`
predates the Nov 1 tuning and the issue-15 engine fixes (layering
train fires 17 stale vs 140 fresh; scatter self-mid over-scores).
`rq5.py` replays train fresh with the current engine/texts
(RQ2 fuzzy arm: pruned from EXACT_FLOOR) unless a reusable file is
passed. Fresh train fires/day: round_trip 32.2, layering 28.0,
scatter 15.8; truncation 0% throughout. The replay graph covers all
days as in RQ2; queries look back only, so no leakage. Motif texts
frozen (sha256 in `rq5_provenance.json`), α=emit untouched.

Cross-checks: the recomputed `gbm` and `motif_union` arms match the
parent `recall_supervised.csv` (gbm_own) and `union_recall_*`
(minrank fuzzy) rows exactly — transfer and instance, all budgets.

## 4. Why stacked underperforms (diagnosis, not tuning)

Stacked early-stopped at iteration 2 (val AUC 0.9753) vs base
gbm_own at 116 (0.9798) under identical hyperparameters. The val-AUC
trajectory explains it: stacked's first tree scores 0.9094 (base
0.9702) — the greedy first split on the sparse motif features does
not generalize to Sep 7 — and val never re-exceeds the iteration-2
peak within patience 50 (0.9722 at iter 49). Run on, it recovers to
0.9803 at iter 127, matching base's 0.9802. So the pre-registered
patience-50 rule got unlucky; the 2-tree model underfits SG and the
motif patterns. Kept as run (fusion only, no recalibration);
follow-up is fixed-iteration or longer-patience stacking.
