# RQ4 first numbers: can Spark write correct motifs? (Nov 3)

Oct 31 plan stage, built overnight: `src/motifql/models/` (Spark client +
repair loop), a 50-item English test set (`eval/rq4_items.py`), and the
harness (`eval/rq4.py`). Question (DESIGN.md §8): share of ~50 English
descriptions that compile within N repair rounds, and witness-set
Jaccard overlap with hand-written references on the training split.

## Method

- **Sample:** 84 train-instance last-member anchors + 1,916 uniform
  background anchors (seed 7, 2,000 total). Reference witness sets
  cached by reference-text hash; model calls cached by prompt hash.
- **Arms:** `repair` (design-faithful §7.1: compile feedback + sanity
  fire-rate feedback, ≤3 attempts), `repair_nosanity` (compile feedback
  only — isolates the sanity step), `oneshot` (single attempt).
- **Metrics:** compile rate (primary), Jaccard over fired witness
  edge-sets vs the reference (secondary; None when the reference fires
  nothing on the sample).
- Model: `muse-spark-1.3` via Meta Model API, `reasoning_effort: low`.
  Server-side prompt caching absorbed the repeated system prompt.

## Results

50 items × 3 arms = 150 runs (`eval/results/rq4_runs.csv`). Three items
were refused by the provider content filter in all arms (see below), so
rates are reported of 50 and of 47 attempted. Jaccard n=43 per arm
excludes the 4 uninformative references (0 fires) and the 3 refused
items; failed compiles count as 0.0.

| arm | compiled /50 | compiled /47 | Jaccard (all rows) | perfect | zero |
|---|---|---|---|---|---|
| repair | 47 (94%) | 47 (100%) | 0.629 (n=43) | 20 | 5 |
| repair_nosanity | 47 (94%) | 47 (100%) | 0.957 (n=43) | 38 | 1 |
| oneshot | 44 (88%) | 44 (94%) | 0.888 (n=43) | 36 | 4 |

(Compiled-only means flatter the baseline: oneshot is 0.954 over the 40
it compiled. The all-rows +0.07 for compile feedback is the honest
comparison.)

Uninformative references (0 fires on the sample, Jaccard None):
structuring-basic, scatter-6h-window, scatter-full, butterfly-quick
(+ structuring-5k, refused). These need a bigger sample or looser refs.

## Finding 1: compiler-error feedback works (3/3)

The model’s characteristic first-try mistake is quantifying over an
EDGE variable in groups (`at least 3 e:`, `few e:`, `at least 2 p:`).
The E_PLAN message (“quantifier over `e`, which is not a group member …
quantify over one of ['r']”) fixes all three on round 2
(fanout-at-least-amount, fan-few-large, gather-at-least-payout — all
Jaccard ≈1.0 in `repair_nosanity`). This is the checks-as-feedback
design working as intended, and a live validation of F4’s E_PLAN:
without it these would have compiled to silent constants instead of
repairing. (In the full `repair` arm the E_PLAN fix lands but sanity
feedback then degrades all three to 0.14/0.11/0.13 — see Finding 2.)

## Finding 2: sanity-rate feedback HURTS (−0.33 Jaccard, paired)

The design’s step 4 (“matches nothing → loosen, >20% → tighten”) is the
only difference between `repair` and `repair_nosanity`, and it degrades
16 items by >0.2 while improving zero (paired mean −0.328, n=43). Two
sub-mechanisms, from the cached repair prompts:

- **Loosen (5 items):** a CORRECT but rare motif fires 0/400 sanity
  anchors, gets “loosen”, and widens into a wrong motif. cycle-long
  round 1 was identical to the reference; round 2 widened hops
  3..6→2..6 and window 14d→21d (1.00→0.11). Same in chain-quick,
  chain-amount-tight, chain-amount-only, scatter-gap.
- **Tighten (11 items — the majority):** a correct round-1 motif fires
  on 26–72% of sanity anchors and gets “tighten” into a wrong motif.
  gather-basic (1.00→0.05), gather-wide, gather-emit-low, fanout-basic,
  fanout-12h, fanin-most-small, chain-all-but-1, and the three Finding 1
  items after their E_PLAN fix.

Neither branch is trustworthy: run on the hand-written references
themselves, the rule flags **32 of 50** (17 loosen, 15 tighten).
Correct references routinely fire above 20% (chain-patient-loose 88%,
gather-wide 72%), so an asymmetric “flag over-broad only” fix would
keep all 11 tighten degradations (paired drop −0.33→≈−0.21, not fixed).

Part of the damage is harness skew on top of the design flaw: the
sanity “sample” is `sample[:400]` — the first 400 of a time-sorted
sample, i.e. Sep 3–4 only, and a subset of the eval anchors.
gather-basic fires 28% on that slice vs ~11% on a random 400, crossing
the tighten line only because of the slice. Follow-up: a fixed
fire-rate threshold cannot separate correct from wrong here. Either
drop rate feedback (keep crash feedback — `repair_nosanity` is 0.957),
or compare against a reference-free prior rather than fixed cutoffs;
and draw sanity anchors as a seeded random subset, ideally disjoint
from eval.

(One `repair` failure needs a correction, not a mechanism: scatter-gap
round 3 was a reasoning-exhausted cut-off — 4000/4000 tokens, 3998 of
them reasoning, empty content — which the client cached and replayed.
Empty/cut-off replies are now retried, never cached; the loop falls
back to the last compiling candidate; the rerun round 3 compiled, so
repair is 47/47 attempted, not 46.)

## Finding 3: provider content filter misfires on benign prompts

structuring-5k, scatter-all-but-1, scatter-time-diff were refused (400
content_policy_violation) in every arm. The filter is flaky, not
deterministic: structuring-5k’s English alone failed, then passed 3/3
identical retries; the system prompt + trivial English passes. Bisecting
further was not worth the calls. Mitigation: that one 400 kind is now
retried like a 429, with a test. The 3 items stay failed rows (kept as
data, not reworded — rewording to dodge a safety filter would taint the
instrument).

## Error classes (round-1, shared by all arms)

- **Instrument ambiguity (1):** gather-count-only English (“collects
  from 3+ accounts”) underdetermines fan-in vs gather; the model wrote
  the natural fan-in, the reference is an x-gated gather → Jaccard 0
  despite both being defensible. V2 should pin the shape in English.
- **Near paraphrase (1):** cycle-step-delay (graded 6–12h gap term vs
  crisp ≤12h, Jaccard 0.33) — the expected Jaccard behavior for a
  close-but-not-identical reading.
- **Reference bug, fixed (1):** fanout-most-big English states no upper
  bound, but the reference capped `big` at $1M; the model’s
  `ramp(1000 USD, 5000 USD)` was the faithful reading. Reference fixed
  to the ramp; all three arms now 1.00.
- **Unpinned conjunction (1):** fanin-count-most (0.86) comes entirely
  from min vs product — swapping only the reference’s `min` for
  `product` reproduces the model’s 12 witness sets exactly. “Both hold”
  doesn’t pin which to use.

## Cost and reruns

Total model spend: 274K input / 121K completion tokens across 99 cached
calls. Reruns are free (prompt-hash cache) and resume by default:
`uv run eval/rq4.py --arms repair,oneshot` picks up missing rows only.
`--check` compiles all 50 references with no model or data.
